Memoria 改进计划
================

按影响大、实现成本低的优先级排序。

一、立刻该做的（成本低、收益大）
--------------------------------

1. API Key 安全
   现状：Key 存在浏览器 localStorage，前端明文暴露。
   改进：后端已有代理能力，前端不再暴露 Key，Key 只存服务端。
   状态：已完成

2. 记忆置信度 + 自动衰减
   现状：用户画像有 confidence 字段但没用起来，错误推断会永久固化。
   改进：
   - 提取画像时 LLM 同时输出置信度
   - 每次提及更新 last_mentioned 时间
   - 低置信度或长期未提及的条目自动降权，不注入上下文
   - 用户可手动标记"不准确"来删除条目
   状态：已完成

3. 主动消息静默策略
   现状：用户不回复时引擎仍会不断触发，造成骚扰感。
   改进：
   - 记录每次主动消息后用户是否回复
   - 连续 2 次无响应自动暂停该类型主动消息
   - 用户下次主动对话后恢复
   状态：已完成

二、值得做但不急的
--------------------------------

4. 摘要自评置信度
   让 LLM 给摘要打分，低于阈值标记存疑，不写入核心画像。
   实现简单但效果取决于模型质量。
   状态：已完成

5. 结构化日志
   用 logging 模块替代 print，记录上下文构建的 Token 分布、
   检索出的摘要条目、主动触发原因。调试时很有用。
   状态：已完成

6. 记忆冲突检测与修正
   当新提取的画像与已有画像矛盾时，自动检测并提示用户修正。
   例如：用户之前说"喜欢Java"，现在说"改用Python"。
   改进：
   - update_profile_batch 中对同 category 已有条目做相似度比对
   - 检测到冲突时 LLM 仲裁，或直接提示用户确认
   - 冲突条目标记为 conflict 状态，等待用户决定
   状态：待实现

7. 关系阶段模型
   定义可量化的关系阶段（初识/熟悉/亲密/家人），不同阶段注入不同风格。
   改进：
   - 根据对话天数、消息数、用户主动分享频率自动演进
   - 阶段变化时记录成长日志
   - 不同阶段影响系统提示中的说话风格
   状态：待实现

8. LLM 调用容错
   为后端 generate 增加指数退避重试，429 限流自动等待。
   流式调用前端重试 + 断线重连。
   状态：已完成

9. 前端弱网处理
   请求超时、流式断线重连、网络状态横幅、离线提示。
   状态：已完成

10. 前端体验优化
    记忆面板自动刷新、流式消息错误重试、部分响应保留。
    状态：已完成

三、进阶方向（复杂度高）
--------------------------------

11. 向量检索
    用 embedding 模型做语义召回 + 关键词双路混合。
    需引入 sentence-transformers + faiss/chromadb，增加部署复杂度。

12. 上下文动态压缩
    对选中的记忆片段进行二次压缩、结构化重组、分区注入。
    需观察 token 使用情况再决定是否做。

13. 偏好学习引擎
    监听用户隐式反馈（快速追问、被纠正）调整回复风格。
    信号太少，不建议现在做。

14. 数据库异步化
    迁移到 async SQLite 库释放 FastAPI 异步优势。
    单用户场景收益小，暂不做。

15. 单元测试
    为 relevance_engine 排序、token_estimator 计算等纯函数编写测试。
    优先级最低。
