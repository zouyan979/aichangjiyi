Memoria 改进计划
================

按影响大、实现成本低的优先级排序。

一、立刻该做的（成本低、收益大）
--------------------------------

1. API Key 安全
   现状：Key 存在浏览器 localStorage，前端明文暴露。
   改进：后端已有代理能力，前端不再暴露 Key，Key 只存服务端。
   状态：待实现

2. 记忆置信度 + 自动衰减
   现状：用户画像有 confidence 字段但没用起来，错误推断会永久固化。
   改进：
   - 提取画像时 LLM 同时输出置信度
   - 每次提及更新 last_mentioned 时间
   - 低置信度或长期未提及的条目自动降权，不注入上下文
   - 用户可手动标记"不准确"来删除条目
   状态：待实现

3. 主动消息静默策略
   现状：用户不回复时引擎仍会不断触发，造成骚扰感。
   改进：
   - 记录每次主动消息后用户是否回复
   - 连续 2 次无响应自动暂停该类型主动消息
   - 用户下次主动对话后恢复
   状态：待实现

二、值得做但不急的
--------------------------------

4. 摘要自评置信度
   让 LLM 给摘要打分，低于阈值标记存疑，不写入核心画像。
   实现简单但效果取决于模型质量。

5. 结构化日志
   用 logging 模块替代 print，记录上下文构建的 Token 分布、
   检索出的摘要条目、主动触发原因。调试时很有用。

三、进阶方向（复杂度高）
--------------------------------

6. 向量检索
   用 embedding 模型做语义召回 + 关键词双路混合。
   需引入 sentence-transformers + faiss/chromadb，增加部署复杂度。

7. 人设成长可解释性
   设计关系阶段模型，量化亲密度、对话天数等指标。
   目前优先级不高。
